# H3 Ref2V 视频流水线

本 Skill 负责探测素材、构建单分支 ComfyUI API workflow、规划多段任务和完成成片收尾。场景切换、RTX 4090 独占、任务排队、ComfyUI 提交、进度监控、恢复原场景和回调必须交给 `axis-video` Skill 提供的工具；不要直接启停 NInfer、ComfyUI 或 AXIS 管理的其他服务。

## 输入素材

用户提供下载链接时先按既有浏览器获取流程下载；用户提供绝对路径时直接核验。用户没有提供下载链接或路径、只说了视频或图片名称时，先运行 `scripts/resolve_shared_input.py <名称>`，默认从 AXIS `file_service_root` 下的 `输入/` 目录解析；根目录已配置为非默认值时传 `--root <实际根目录>`。解析器只接受单个文件名或唯一的不带扩展名名称，只允许视频和图片；找不到、重名或最终路径逃逸时直接报告，禁止改查工作目录、下载目录或其他位置。`build_api.py --source` 也遵循同一规则，并将解析出的绝对视频路径写入 workflow。

## 执行模式

- 视频换装或移除遮挡物任务默认使用免检快速模式：除非用户明确要求“检验”“验证”“验收”“检查成片”或“制作样片”，否则禁止生成 preview/sample，禁止生成用于成片验收的截图，禁止视觉验收、成片 `ffprobe` 检查和音频哈希检查，也不得后台补做。保留生成提示词所必需的源片参数探测和源片视觉分析，源片分析完成后直接构建并提交正式工作流。交付时标注“默认免检，结果未检验”，不得声称 PASS。
- 换装或移除遮挡物任务的明确检验模式：只有用户明确要求检验时才启用，并且只执行用户要求的检验范围。用户笼统要求检验、验证或验收时，正式生成后检查用户要求的媒体流并按截图隔离规则抽帧验收；用户只要求样片时仅制作并检查样片，不自动扩大到成片验收。
- 免检只省略样片和成片检验，不放宽单分支、帧数、资源门槛、AXIS 串行调度、不覆盖原文件、安全分段、拼接、格式转换或音频回填等规则。
- 其他类型的 Ref2V 任务继续使用正常模式：可先做短预览，正式生成后检查媒体流并抽帧验收。

## 所有截图的强制隔离

以下规则适用于本流水线中创建、接收、读取或比较的所有截图，不限执行模式和阶段，包括源片分析、提示词编写、镜头切分、预览检查、生成中排障、成片验收、历史结果对比和界面截图：

- 主会话禁止直接加载、查看或使用任何截图的图像内容，也不得用图片附件调用视觉能力。
- 每张截图必须交给一个全新独立视觉子代理；每个子代理在整个生命周期内最多读取一张截图，只返回文字，不得把图片或新的截图带回主会话。
- 源片分析子代理返回 `截图路径 + 时间戳 + 可观察事实 + 不确定项`；验收或对比子代理返回 `截图路径 + PASS/FAIL + 可观察事实 + 理由`。主会话只汇总这些文字结果。
- DOM、视频元数据、场景检测数值、像素统计、历史摘要和旧检测报告不能代替本次截图的独立视觉识别，也不能据此补写截图中未被识别的事实。
- 子代理不可用、读图失败、图片触发上下文压缩或缺少任一截图的文字结果时，立即明确报告对应视觉步骤未完成；不得由主会话降级读图，也不得把同一截图转交给已经看过其他截图的子代理。

每次任务都新建唯一任务 ID，并把本次源片截图的子代理文字结果保存为固定文件名 `source_detection_report.json`。报告必须记录任务 ID、带时区的创建时间、源片绝对路径和 SHA-256，以及最终 `prompt.txt` 的 SHA-256；每帧记录截图绝对路径、SHA-256、格式、尺寸、时间戳、唯一子代理会话 ID 和非空文字结果。镜头边界和不确定项只允许从这些结果及非视觉媒体探测数据汇总。提示词必须依据本次报告和本次用户要求重新编写，写完后将其哈希加入报告；禁止复用旧报告或旧提示词。缺少有效报告时，`build_api.py` 必须拒绝生成 workflow。子代理身份目前由 OpenCode 的真实子代理会话 ID 记录，禁止自行编造字符串。

## 工作流基线

基线随 Skill 一起安装，始终从 Skill 目录解析，不依赖历史任务目录：

- 4 步快速版：`assets/h3-ref2v-4step-api.json`
- 8 步质量版：`assets/h3-ref2v-8step-api.json`

默认使用 8 步。用户明确要求快速时使用 4 步；只有用户明确要求比较时才分别制作对比预览，不要擅自生成两个正式版本。基线中的源片、提示词和输出前缀都是占位值，每次必须通过 `scripts/build_api.py` 覆盖。

8 步基线必须从 LoRA 直接连接 Sigma Shift，不插入 `PathchSageAttentionKJ`。当前 SageAttention 与 AIMDO/DynamicVRAM 异步权重卸载存在崩溃风险；在兼容性得到单独验证前不得重新加入。移除 SageAttention 不得改变 8 步、分辨率、模型或 LoRA。

## 参数与分段

1. 用 `ffprobe` 记录源片分辨率、帧率、视频流时长、帧数和音频流。
2. 生成帧率固定 24 fps。`length` 必须满足 `17n+5`；使用不小于目标窗口帧数的最小网格值。
3. 宽高必须为正数且是 16 的倍数。8 步短边默认 768，长边按原比例取最接近的 16 倍数；4 步短边默认 448。
4. 未经新的容量验证，RTX 4090 单段最多 200 帧。更长的视频必须拆成多个独立 workflow，优先在真实硬切点处分段；没有硬切点时按帧数均分。
5. 每个 workflow 只能有一个 `MiniMaxH3ReferenceToVideo` 和一个生成采样分支。多段任务保持同一 seed，并按时间顺序一次调用 `axis_video_submit_batch`，禁止逐段预提交或把多段合并为一个多分支图。
6. 网格输出可能长于目标窗口。拼接前按各段窗口帧数裁剪，拼接后再按源片时长收尾。

构建单段工作流：

```powershell
python scripts\build_api.py `
  --baseline assets\h3-ref2v-8step-api.json `
  --source <source.mp4> `
  --detection-report <source_detection_report.json> `
  --task-id <unique-task-id> `
  --width 768 --height 1344 --length 107 `
  --prompt-file <prompt.txt> `
  --prefix <task-tag>/segment-01 `
  --out <segment-01.json>
```

`--skip-frames` 可从源片指定的 24 fps 帧序号开始读取，用于分段而不预切视频。构建脚本会在写文件前验证基线、任务 ID、源片/截图/提示词哈希、截图格式和尺寸、检测报告、尺寸、网格帧数、跳帧值和必要节点；成功后同时生成 `<workflow>.evidence.json`，绑定 workflow、源片、报告和提示词的绝对路径及 SHA-256，供 AXIS 插件提交前再次校验。脚本输出证据文件、报告路径与识别帧数、LoRA、采样步数、尺寸、帧数、seed、源片、跳帧值和输出前缀供核对。

## 提示词

提示词使用英文并严格采用下述六段结构。身份、动作、镜头和时间线只通过 `<Video 1>` 全局引用锁定，不得逐项或逐时间窗重述；逐镜头或必要时间窗的视觉描述只写变化区域、交界与遮挡层级。提示词中的视觉事实只能来自本次 `source_detection_report.json`；无法确认的内容必须保留为不确定，禁止猜测。多段视频的时间戳相对各段起点重算；同一人物跨段保持一致描述和 seed。

本节的 Ref2VA 六段规则是提示词写作的唯一规范。不得调用面向 I2V/I2VA 的 `minimax-h3-prompt` Skill 来决定格式，也不得为了“对齐写法”搜索、读取或复用既往任务的提示词、成片说明或工作流内嵌提示词。历史 API JSON 只可作为节点图基线，并且必须用本次依据源片和用户要求新写的提示词覆盖其中旧值。

所有换装或移除遮挡物任务都必须在提示词靠前位置明确以下约束，不以是否露出源片中不可见区域为条件：

- 最高优先级硬约束：只允许用户指定的变装或遮挡区域发生变化；变化区域之外的所有源片可见内容不得发生任何变化。脸、头发、源片裸露皮肤、手、道具、姿态、动作、镜头、构图、光线、背景和时间线全部由 `<Video 1>` 锁定。提示词不得重新设计、重新描述或逐项改写这些未变化区域。
- `summary` 只写一句编辑边界和全局锁定：`[video editing] The target video is an edited version of <Video 1>. The only permitted visual change is the requested clothing or occlusion edit on <Subject 1>; every source-visible element outside the edited region must remain unchanged from <Video 1>.` 衣物或遮挡物塑造了外形时，不得要求 `body outline unchanged`；只保留源片实际可见的人体比例和轮廓，衣物塑造的外轮廓属于变化区域。
- 仅当编辑确实露出源片中不可见的身体区域时，源片中可见的身份、体型比例、姿态、动作节奏和镜头透视才作为合理补全的连续性锚点；不得声称从源片精确保留了不可见细节。
- 仅当存在上述新露出区域时，该区域必须与相邻可见区域组成同一个连续身体并随源片动作同步；骨骼标志、关节活动、重力、软组织拉伸与压缩、接触形变和自身遮挡符合真实解剖及当前视角，不能出现重复、融合、断裂或滑动的结构。
- 变化区域的新内容只以相邻的源片可见区域作为局部颜色、材质、比例和受光基准；这些基准本身保持不变且不在逐镜头描述中重复展开。新内容保留真实的局部差异和连续受光，禁止新增分色、色漂、色斑、闪烁、瓷感、蜡质、塑料感或磨皮。
- 严格按官方 Full-Reference Mode 的六段顺序放置这些信息：
  - `subject_definitions`：定义 `<Video 1>` 为被编辑的完整源视频，定义 `<Subject 1>` 为其中接受变装或遮挡编辑的主体；只记录变化区域的源片衣物/遮挡事实及完成变化所需的相邻可见基准，不展开描述未变化区域，也不得假装引用源片未展示的细节。
  - `summary`：使用上面的固定一句，声明唯一允许的变化和 `<Video 1>` 全局锁定，不堆叠质量词。
  - `retention_analysis`：使用官方固定标记格式 `<Subject 1>: partially_preserved - ...`，只说明指定区域变化且变化区域之外完全保留；不得使用方括号包裹标记，也不得把源片未展示的细节标成 `fully_preserved`。
  - `detailed_description`：所有视觉描述只针对变化区域。按真实镜头或必要时间窗描述该区域的目标状态、局部补全、受光和随源片运动的形变；不得逐时间段重复描述未变化区域，不得重述脸、发型、表情、手势、道具、背景或镜头。手或道具穿过变化区域时，只描述遮挡边界和前后层级，并明确它们本身保持 `<Video 1>` 原样。
  - `overall_soundscape` 和 `non_diegetic_music` 只描述声音，不混入解剖或画质要求。
- 提示词较长时优先保留 `subject_definitions`、`retention_analysis` 和逐时间窗的关键约束，不要把它们放在容易被忽略的末尾。

提示词必须短而具体，1600–2200 个 UTF-8 字节只是常规软目标，不是完整性的硬上限：

- `subject_definitions` 每个引用一行；必须定义 `<Video 1>` 和 `<Subject 1>`，只写变化区域及其必要局部基准，不写未变化区域的外观清单。
- `summary` 用一句话概括编辑边界；`retention_analysis` 每个引用一行说明保留/变化关系；`detailed_description` 在镜头中落实可见事实。三个字段各写自身职责，但不得逐字复制整段约束或完整负面词清单。
- `detailed_description` 每个真实镜头一段，但所有视觉描述只针对变化区域：只写该区域实际可见且可判断的源片遮挡事实、目标状态、局部匹配、运动形变及必要的遮挡层级；不存在、被遮挡或无法判断的项目不得猜测。未变化区域只由全局锁定约束保留，不得逐镜头重复。每个涉及编辑区域的镜头都必须写明该镜头中的目标状态，不得只在 `summary` 或结尾用一句 `Throughout` 代替。
- 以下信息属于不可删减项：唯一编辑边界和全局锁定；源片实际衣物或遮挡物的名称、材质、轮廓和覆盖范围；每个相关镜头中的目标状态；与变化区域相交的手、道具、运动模糊和自身遮挡边界；必要的局部基准与补全关系；与本片或已确认失败直接相关的负面约束。不得为了满足长度删除、合并成抽象概括或移到弱化位置。
- 负面约束通常保留与源片和已确认失败直接相关的 4–8 项，不堆叠通用质量词；已确认失败项不得因数量或长度删除。移除衣物或遮挡物时，必须依据源片的实际结构排除残留衣物轮廓、腰头/腰带/口袋/门襟等可见结构、肤色衣物状色块和模糊不透明遮挡；源片不存在的结构不得凭空加入负面词。
- 写入 workflow 前计算字节数。超过软目标时，依次删除重复句、抽象形容词、重复身份命令和无关负面词；上述不可删减项仍无法完整容纳时允许超过 2200，不得截断语句或牺牲逐镜头完整性。

需要保留源片音频时，生成 workflow 可以只输出视频，完成后用 `finish_video.py` 回填。需要模型原生音效或音乐时，工作流必须使用能同时解码视频和音频 latent 的节点，并把生成音频接到最终视频节点；不得把无声输出误报为含音频。

## 提交与收尾

- 单段正式任务调用 `axis_video_submit`。
- 多段正式任务把全部单分支 JSON 按顺序一次传给 `axis_video_submit_batch`。AXIS 会逐段释放生成模型，批内不恢复场景、不回调，批尾统一恢复并回调一次。
- 失败后只重建、重提失败片段；保留已完成片段，不得重复生成。
- 取消是终态。收到取消结果后不得重新生成或重新提交已取消任务，也不得继续同批后续片段；只有用户在取消之后提出新的明确生成要求时，才可创建新任务。取消不得套用失败重试规则。
- AXIS 输出可直接传给 `finish_video.py --generated <video>`，回填源片原音频并裁到目标时长。换装或移除遮挡物任务默认免检时不要传 `--verify` 或 `--report`；这些任务被明确要求检验音频时，以及其他 Ref2V 任务按正常模式收尾时，都传 `--verify --report <报告名>`。输出已存在时脚本必须拒绝覆盖。

换装或移除遮挡物任务中，用户明确要求检验时按其要求用 `ffprobe` 确认相应音视频流和时长，并按“所有截图的强制隔离”执行所需视觉验收；默认免检快速模式跳过预览和成片验收。为本次提示词生成源片检测报告仍是必需步骤，并同样受截图隔离规则约束。其他类型的 Ref2V 任务仍按正常模式验收。

需要局域网交付时，复用 AXIS 的固定 HTTP 文件服务，当前约定端口为 `18765`、根目录为 `D:/共享/`。它不是 `python -m http.server`：健康检查使用 `GET /health`，目录列表使用 `GET /api/v1/files`，文件读取使用 `GET /api/v1/files/content?path=<URL 编码的相对路径>`。根路径 `/` 返回 404、文件内容接口对 `HEAD` 返回 405 都不表示服务异常。工具调用之间不共享 PowerShell 变量；每次调用必须在同一条命令内定义并使用变量，且在读取响应头前先确认请求成功。不得另外启动临时文件服务，也不得停止或接管未知监听。交付前验证真实局域网 URL 返回 HTTP 200。

需要登录的站点只能使用已登录的可见浏览器会话，或请用户在可见界面完成登录。不得读取、复制或解密浏览器 Cookie 数据库，不得把 Cookie、会话令牌或其他认证值写入提示词、命令、日志或任务文件。无法在可见浏览器中取得素材时，必须明确报告阻塞，不得用本地凭据绕过。

## 自带资源

- `assets/h3-ref2v-4step-api.json`：去敏的 4 步单分支 API 基线。
- `assets/h3-ref2v-8step-api.json`：去敏的 8 步单分支 API 基线。
- `scripts/build_api.py`：从基线构建一个单分支 workflow。
- `scripts/build_api_batch.py`：仅用于读取或迁移旧的多分支图；不得将其输出提交给 AXIS。
- `scripts/submit_wait.ps1`：仅在明确要求绕过 AXIS、直接调试独立 ComfyUI 时提交并等待单个 prompt；不能用于场景切换任务。
- `scripts/submit_multi.ps1`：仅在明确要求绕过 AXIS、直接调试独立 ComfyUI 时提交多个独立 prompt；不能用于场景切换任务。
- `scripts/finish_video.py`：按源片参数收尾；默认不检验，新调用只有传入 `--verify --report <报告名>` 时才验证原音频一致性并写报告。为兼容旧调用，单独传入 `--report` 也视为明确启用检验。

所有脚本错误必须直接报告根因。AXIS 工具报错时原样说明，不要绕过调度器继续切换服务或重复提交。
