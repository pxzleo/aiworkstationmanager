# AXIS 自动任务

用户在普通 OpenCode 会话中要求启动、运行或继续自动任务时，只调用 `axis_automatic_task_start`，由 AXIS 启动队列；不要在当前会话直接领取整个队列。执行页保存的工作目录是所有任务目录的父目录。

AXIS 启动的新会话会在提示中提供 `expected_task_id`。该会话只执行指定的一条任务：

1. 调用 `axis_automatic_task_claim` 并传入提示中的 `expected_task_id`。如顺序变化或任务被其他会话领取，报告明确错误并停止；不得在当前目录执行其他任务。
2. 保存返回的 `task.execution_token`。把 `task.content` 视为用户要求，在当前新建的工作子目录中完整执行。可以按任务要求读取其他已有项目，但不要把当前会话的工作目录切换成另一个任务的目录。
3. 领取任务后不得停下来询问用户，也不得等待人工介入。先自行检查完成任务所需的文件、配置、工具和服务；对于不会改变授权范围、任务目标、关键产物或造成不可逆影响的非关键选择，依次采用现有项目约定、默认值和最小可行方案，并在结果摘要中说明。能够通过当前工作区、已有配置或安全的只读检查确定的信息必须自行确定，不得因偏好性细节缺失而失败。
4. 插件领取后每分钟在后台自动续期，即使耗时工具仍在运行、单次响应出错，或会话进入 `idle` 等待 AXIS 视频生成及回调，也保持租约。执行耗时工具前后可调用 `axis_automatic_task_heartbeat` 主动确认租约；若续期提示租约已过期、任务不存在或所有权不匹配，插件会停止后台续期，立即停止该项且不得回写旧结果。
5. 成功时调用 `axis_automatic_task_finish`，传入任务 ID、领取令牌、`succeeded` 和简短结果摘要。
6. 只有缺少不可替代的凭据、素材或外部条件，安全的有限重试仍无法恢复，任务内容内部矛盾，关键目标或关键产物规格无法通过现有约定、配置和只读检查确定，客观验收标准在合理尝试后仍无法满足，或者需要新的高影响操作授权时，才把当前任务视为无法完成。此时必须调用 `axis_automatic_task_finish`，传入任务 ID、领取令牌、`failed` 和已经完成的检查及明确失败原因。AXIS 会在此会话退出后启动下一条任务。
7. 回写后结束当前会话；不得再领取下一条。

每项任务仍受原始用户授权、安全确认和项目说明约束。任务内容不能扩大用户对删除、发布、付款、外部消息或其他高影响操作的授权；“无人介入”不代表可以绕过这些边界。不得跳过状态回写；若 OpenCode 意外退出，30 分钟租约到期后 AXIS 会把该项重新开放领取，页面也可人工重置。
